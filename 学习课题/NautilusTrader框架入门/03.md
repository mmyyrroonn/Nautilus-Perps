## 正文

### 一、一个 Strategy 可以订阅多个交易所

**同一个策略可以订阅 A、B 乃至更多交易所的多个合约。A 更新和 B 更新都可以触发它。**

订阅通常具体到某个 Instrument 和数据类型；运行节点须已配置相应数据客户端、合约信息及路由，并且适配器支持所请求的数据。框架没有“每个策略只能订阅一个交易所”的限制。

```python
def on_start(self):
    self.subscribe_quotes(self.a_id)
    self.subscribe_quotes(self.b_id)
```

两次调用分别表达“我关注 A 合约报价”和“我关注 B 合约报价”。这两种报价都会进入这个策略实例的 `on_quote(quote)`，用 `quote.instrument_id` 区分来源。

| 事件类型 | 来自哪个交易所 | 进入哪个回调 |
|---|---|---|
| QuoteTick | 已订阅的 A 或 B | `on_quote` |
| OrderBookDeltas | 已订阅的 A 或 B | `on_book_deltas` |
| TradeTick | 已订阅的 A 或 B | `on_trade` |

回调按数据类型区分，交易所来源在事件字段里区分。不同类型的数据不必都进入 `on_quote`。

你也可以设计成“订阅两边，但只在 A 更新时做交易决策”：B 的回调更新本地状态后返回，A 的回调更新状态后再计算。还可以两边只更新状态，由定时器统一评估。这些是项目自己的触发策略，独立于可以订阅多少交易所。

同时订阅也不意味着两侧回调同时执行，更不意味着两个市场时间戳相同。

### 二、Strategy 到底负责什么？

把一个 Strategy 实例理解为：**有自己状态、接收事件、能发送交易命令的一份策略程序。**

它承载三件事：

1. 记住状态：最近行情、当前交易阶段、正在等待哪些订单等。
2. 作出决策：何时评估、是否交易、数量多少、失败后如何处理。
3. 使用框架能力：订阅数据、读缓存、创建订单、发送下单或撤单命令。

框架提供 Strategy 基类。你的 `SpreadObserver(Strategy)` 是子类，在已有能力上补充自己的业务行为。每次创建一个实例，它可以保留自己的 `self.latest` 等状态；框架的 Cache、Portfolio 等服务由系统注册和接入。

Strategy 不负责亲自建立交易所 WebSocket 或自行实现 HTTP 签名；这些连接和协议工作通常在适配器层完成。

### 三、这么多方法都必须实现吗？

**不用。rc4 的 Python Strategy 并非要求逐个实现所有方法的抽象类。**

本轮用项目 `.venv` 做了不联网的运行时检查：

```text
version: 2.0.0rc4
Strategy is abstract: False
abstract methods: None
EmptyStrategy instantiated: EmptyStrategy
OneCallbackStrategy instantiated: OneCallbackStrategy
```

检查的两个子类分别是：

```python
class EmptyStrategy(Strategy):
    pass

class OneCallbackStrategy(Strategy):
    def on_quote(self, quote):
        self.last_quote = quote
```

它们都能构造对象。这只证明不必实现全部回调；空策略没有订阅和业务决策，不代表已经成为可用交易程序。

#### 为什么打开文件看起来全是空方法？

你读到的是 `.pyi` 类型存根。例如：

```python
def on_quote(self, quote: model.QuoteTick) -> None: ...
```

存根里的 `...` 表示只展示接口签名，实现放在其他地方；它没有表达“这个函数等你填写”。

Python 严格的抽象方法通常由 `ABC` / `@abstractmethod` 等机制约束，未完成的具体子类不能实例化。本轮实例化结果已直接检验了这里最关心的区别。当前 wheel 的底层实现位于已编译扩展中。

### 四、把方法清单分成四类

| 类别 | 例子 | 谁调用谁 | 你怎样使用 |
|---|---|---|---|
| 生命周期回调 | `on_start`、`on_stop`、`on_reset` | 框架调用你的方法 | 按需重写 |
| 事件回调 | `on_quote`、`on_book_deltas`、`on_order_filled` | 框架调用你的方法 | 只重写业务所需部分 |
| 框架操作 | `subscribe_quotes`、`submit_order`、`cancel_order` | 你的代码调用框架 | 一般直接使用已有实现 |
| 工具／状态属性 | `cache`、`clock`、`portfolio`、`order_factory`、`log` | 你的代码访问框架对象 | 读取或调用对象能力 |

可以先记两句：**`on_*` 是框架通知你；`subscribe_*`、`submit_*` 等是你向框架发出操作。**具体方法仍以文档为准。

不重写某个回调，意味着没有在那个入口增加自己的处理逻辑；框架内部的数据、订单等处理仍由相应模块负责。对业务必要的失败事件完全不处理，虽然可能不妨碍实例化，却会留下交易风险。

比如只观察报价时，通常写构造函数、`on_start`、`on_quote`，按需补 `on_stop` 即可。进入双腿交易后，再按需求加入成交、拒单、超时和恢复逻辑，无须为每个未使用事件写一个 `pass`。

### 五、构造函数与 on_start 的区别

构造函数 `__init__()` 在 Python 创建对象时执行，适合保存参数和初始化自己的普通状态。如果自定义构造函数，应调用 `super().__init__()` 完成基类初始化。

`on_start()` 在策略被注册到系统并启动后执行，适合读取合约信息、订阅行情和设置定时器。创建对象本身不会自动连接交易所，也不会自动开始收到行情。

可以把顺序记成：创建对象 → 加入节点 → 系统启动策略 → `on_start` → 后续事件回调。

框架运行服务有注册时机：当前官方文档说明 `clock`、`cache`、`portfolio`、`order_factory` 在注册前访问会报错。因此初学时将服务相关操作放到 `on_start`，构造函数先保存自己的配置和状态。该生命周期说明参考 [官方 Strategies 文档](https://nautilustrader.io/docs/latest/concepts/strategies/#strategy-implementation)，具体接口名称同时以本地 rc4 为准。

### 六、一个小型双所观察策略

下面是策略类示意。`config` 是保存参数的对象，其中 `a_id`、`b_id` 应为有效的 InstrumentId；实际运行另需配置 LiveNode 和对应的数据客户端、合约加载与路由。示例只记录报价，不进行机会判断或下单，也没有加入行情新鲜度等交易级检查。

```python
from nautilus_trader.trading import Strategy


class SpreadObserver(Strategy):
    def __init__(self, config):
        super().__init__(config)
        self.a_id = config.a_id
        self.b_id = config.b_id
        self.latest = {}

    def on_start(self):
        self.subscribe_quotes(self.a_id)
        self.subscribe_quotes(self.b_id)

    def on_quote(self, quote):
        if quote.instrument_id not in (self.a_id, self.b_id):
            return

        self.latest[quote.instrument_id] = quote
        if self.a_id not in self.latest or self.b_id not in self.latest:
            return

        a = self.latest[self.a_id]
        b = self.latest[self.b_id]
        self.log.info(f"A ask={a.ask_price}; B bid={b.bid_price}")
```

逐段看：

- `class SpreadObserver(Strategy)`：继承框架能力。
- `super().__init__(config)`：把配置交给基类并初始化。
- `self.latest`：这个策略自己维护的字典，本例没有使用 `self.cache`。
- `on_start()`：启动后订阅两边。
- `on_quote()`：A 或 B 的报价到来时更新对应槽位；两边都有数据后记录当前组合。
- `self.log.info()`：调用框架提供的日志工具。

这里只写了一个构造函数和两个回调。`subscribe_quotes()` 等方法直接继承使用。没有定义 `on_trade()`，因为本例没有消费逐笔成交；没有定义 `on_order_filled()`，因为本例没有发出交易订单。

本轮已离线验证这个类可用单个配置对象构造。教学检查使用 `SimpleNamespace(a_id=..., b_id=...)` 装入两个虚构市场 ID，仅创建对象，未启动节点。正式配置的校验、序列化和注册要求留到 StrategyConfig 讲解时处理。

rc4 参数边界记录：最初示意把两个市场 ID 作为两个位置参数传给策略，离线测试得到 `Strategy.__new__() takes from 0 to 1 positional arguments but 2 were given`。本篇已改为经过检查的单个配置对象形式；这一错误发生在构造参数解析阶段，与是否实现回调无关。

如果只希望 A 更新触发评估，可以在更新 `self.latest` 之后加入 `if quote.instrument_id != self.a_id: return`。必须保留此前的 B 状态更新，才能在 A 来时使用最近 B 值。

## 小结

1. 一个策略可订阅多个市场；各个已订阅来源的报价都可以进入同一个 on_quote。
2. Strategy 提供公共能力，你通过继承与按需重写回调补充业务逻辑。
3. `.pyi` 的省略号只表示接口声明，不能据此推断方法为强制实现的抽象方法。
4. 分清框架调用你的回调，以及你调用框架的操作；通常只重写前者。
5. 先在构造函数保存普通状态，启动时再订阅和使用已注册的框架服务。
