# 评估周期与持久化意图唤醒

- `runtime.evaluation_interval_ms` 支持 100 ms 基线、20 ms 小批次及 0（完整行情批次事件触发）。
  默认与现有配置保留 100 ms，风险/对账定时器独立；未用未验证的离线结果直接切换生产频率。
- 成功持久化订单意图后，使用原生时钟一次性事件唤醒完整 `LiveCoordinator.tick`。
  同一轮多个意图只安排一个唤醒；事件不重入当前回调。已被成交/回执回调排空时不重复调度。
  一次性时钟调度失败仍由常规定时器接管，停止时解除通知。持久化失败不通知、不释放订单。
- `coordinator.intent_wakeup` 记录持久化意图就绪至唤醒回调的延迟，复用有界采样统计。

验证：131 项测试通过，包含完整协调器回归、亏损监控、异步调度、合并唤醒、持久化故障与定时器回退。

`scripts/compare_entry_schedules.py` 使用相同的 464 个五所合成事件进行虚拟时间回放，构造持续机会和短暂机会。
各个周期均与同周期全量扫描核对完整订单决策。持续机会的两腿、价格、数量一致：

| 周期 | 评估次数 | 订单意图时点 | 首次更新→发布 p50/p95/p99 |
| --- | ---: | ---: | --- |
| 100 ms | 12 | 600 ms | 93 / 99 / 99 ms |
| 20 ms | 60 | 520 ms | 13 / 19 / 19 ms |
| 事件触发 | 464 | 509 ms | 0 / 0 / 0 ms |

这仅是调度模型，不包含 native 队列、网络、签名或交易所延迟。事件触发的 0 ms 不是实测延迟。
短暂机会在 100 ms 下未产生订单，在 20 ms/事件触发下产生订单；调度改变会改变可见机会集合，不能宣称跨周期逐笔相等。
CPU 由脚本每种配置重复 20 次测量，含建盘及初始化；不同周期的重算次数差异必须纳入生产选型。
