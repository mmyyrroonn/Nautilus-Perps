# 逐笔交易复盘验收 — 2026-10-20

范围为 Python 策略账本与离线分析，不修改原生 fork，不部署、不重启实盘，不改变订单价格、数量、风控与恢复逻辑。既有用户改动保留。

## 实现

- `ExecutionReceipt` 增加默认兼容的固定原因分类、来源和原生状态字段。
- 网关将本地校验失败、原生拒单分类、提交异常与回报超时传给策略；终态需要等待成交核对时，分类保留在既有 owned order 中。
- 复用现有事件事务保存会话编号、订单准备摘要、已有盘口时间、预期限价经济数据、成交美元现金流、拒单原因、平仓经济分项。未增加事务次数。
- `src/opportunity_review.py` 只分析停机账本或一致离线备份。取得既有 owner lock 后以 `mode=ro` 打开 SQLite，遇到实盘占用时拒绝分析。
- 输出开仓/平仓现金流、多空腿毛盈亏、已确认费用、净盈亏和退出记录；不将未知手续费或未解决的成交证据标成最终收益，不推断网络延迟等根因。
- 旧账本兼容读取，缺失字段明确标示；按快照、归档和显式会话编号防止跨会话混单。

用法见 [操作说明](../../../docs/trade-review.md)。[模拟示例](example.md) 与 [详细 JSON](example.json) 均为合成测试数据，不是实盘成交。

## 性能

使用 [benchmark.py](benchmark.py) 对比当前改动与 `HEAD` 中原有三个运行模块。源提交和逐轮数据见 [benchmark.json](benchmark.json)。四轮交替先后顺序、每个进程预热 20 次；CPU/序列化场景每版 800 样本，真实 SQLite `synchronous=FULL` 场景每版 320 样本。

最终一轮独立测量在全量 pytest 结束后运行；初轮与 pytest 有重叠的数据不用于以下结论。数据为本机 Windows 合成测量，不是实盘网络性能。

| 场景 | 原有 p50 / p95 / p99 | 修改后 p50 / p95 / p99 |
|---|---|---|
| 下单准备，含 JSON 序列化、不含磁盘 | 533.9 / 568.1 / 665.9 μs | 555.2 / 598.9 / 686.9 μs |
| 拒单处理，含 JSON 序列化、不含磁盘 | 171.8 / 178.6 / 232.1 μs | 179.6 / 190.0 / 251.3 μs |
| 下单准备，含真实 SQLite | 5.713 / 6.627 / 7.259 ms | 5.856 / 6.674 / 7.621 ms |
| 拒单处理，含真实 SQLite | 10.379 / 11.731 / 12.333 ms | 10.416 / 11.737 / 14.867 ms |

合成循环包括一对订单准备、释放和其中一笔拒单及账户重读请求。**每循环仍为 4 次保存**；事件 JSON 合计由 **715 B 增至 1866 B**，增加 **1151 B**。该字节数不含完整状态快照与 SQLite 页开销。

下单准备的纯 CPU/序列化中位数增加约 21 μs，含 SQLite 中位数增加约 0.14 ms。拒单路径的 SQLite p99 增加约 2.53 ms，存在磁盘尾延迟波动；不能据此承诺零开销或生产环境 p99 不变。没有为追求更好数字重测或放宽持久化设置。策略准备与拒单路径均未新增磁盘事务，未引入在线归因、市场数据全量复制或额外网络请求。

仍需实盘运行后的观测才能判断实际吞吐与尾延迟。本次未访问真实交易账本，也未进行主网交易。
